# 纯视觉 PNG 上视相机项目总体方案

## 1. 项目定位

本项目是一个用于验证纯视觉比例导引（PNG）链路的 Python 仿真、评估和实机适配工作区。当前主线不是单一飞控平台，而是三层递进：

1. 合成数据与单元测试：验证几何、LOS 滤波、TTC 和质量门控。
2. AirSim/PX4：验证固定上视相机、YOLO/ByteTrack、PNG/TTC/VM、PX4 setpoint 映射。
3. Betaflight 实机准备：通过 MSP 读取遥测、记录候选导引量，并在安全门控后输出受限 RC setpoint。

当前代码不把 AirSim/PX4 参数直接搬到 Betaflight。Betaflight 默认不是 PX4 Offboard 架构，实机路径必须走独立的 MSP telemetry / RC 命令适配层。

## 2. 当前系统组成

```text
Camera / CSV replay / AirSim detection
  -> YOLOv8 + ByteTrack 或 AirSim box2D
  -> FrameDetection(frame_id, exposure_ts, bbox, track_id, score)
  -> 姿态缓存 AttitudeHistoryBuffer
  -> 相机内参 + 固定外参 R_BC
  -> 6D LOS Kalman Filter
  -> Scale Expansion TTC
  -> GuidanceEval(g_eval)
  -> 仿真/PX4/Betaflight 输出适配
```

核心目录：

- `vision_guidance/`：几何、姿态缓存、LOS 滤波、TTC、检测适配、Betaflight MSP 与 RC 映射。
- `examples/`：AirSim/PX4 场景、Betaflight log-only / RC 注入 runner、报告生成脚本。
- `config/`：AirSim settings 与 Betaflight 示例配置。
- `tests/`：标准 `unittest` 单元测试。
- `doc/`：当前方案、算法、实施、部署与使用说明。

## 3. 视觉与导引原理

相机只作为测角传感器使用。bbox 中心点 `(u, v)` 通过相机内参转成相机系单位视线，再结合固定外参 `R_BC` 和曝光时刻对应姿态 `R_IB(t)` 转到惯性系：

```text
bbox center -> los_C -> R_BC -> los_B -> R_IB(t_exposure) -> lambda_I
```

LOS 滤波器只估计：

```text
[lambda_x, lambda_y, lambda_z, lambda_dot_x, lambda_dot_y, lambda_dot_z]
```

bbox 面积不进入 LOS 主状态，只进入独立的尺度膨胀 / TTC 通道。这样可以避免 bbox 尺度抖动污染视线角速度。

导引评估量为：

```text
g_eval = K(TTC) * lambda_dot_I
```

在 AirSim strapdown 路径中，代码还支持把 PNG 需用加速度映射到 PX4 velocity、body-rate/thrust 或 attitude/thrust setpoint。Betaflight 路径目前使用 `guidance_command.rate_gain_matrix` 将 `g_eval` 映射为 roll/pitch/yaw rate 候选量，再转为 RC 通道。

## 4. 当前运行路径

### 4.1 单元测试和合成示例

```bash
python3 -m unittest discover -s tests -v
python3 examples/run_synthetic.py
```

用于验证纯算法和数据结构，不依赖 AirSim 或真实飞控。

### 4.2 AirSim/PX4 验证

AirSim 路径使用内置 detection 或 YOLO/ByteTrack，输出 CSV、meta 和图表。PX4 路径支持：

- `velocity_simple`
- `velocity_yaw_rate`
- `mavlink_body_rate`
- `mavlink_attitude`

典型命令：

```bash
python3 examples/run_airsim_strapdown_vision_png.py \
  --enable-motion \
  --detector-source yolo_bytetrack \
  --yolo-model /path/to/model.pt \
  --yolo-class-id 0
```

### 4.3 Betaflight 实机准备

Betaflight runner 默认只读：

```bash
python3 examples/run_betaflight_log_only.py \
  --config config/betaflight.example.json \
  --serial-port /dev/ttyUSB0 \
  --duration-s 60 \
  --detector-source none
```

RC 输出必须显式打开：

```bash
python3 examples/run_betaflight_log_only.py \
  --config config/betaflight.example.json \
  --serial-port /dev/ttyUSB0 \
  --control-mode msp_raw_rc \
  --allow-control \
  --detector-source csv \
  --detections-csv /path/to/detections.csv
```

输出控制前必须完成无桨台架验证、AUX gate、failsafe、通道方向、hover throttle、rate limit 和 `rate_gain_matrix` 标定。

## 5. 安全边界

- 不自动 ARM。
- 不自动切换飞行模式。
- Betaflight RC 输出默认禁用。
- 丢目标、遥测超时、姿态不同步、低电压、watchdog 超时或 AUX 未使能时不进入 active 控制。
- AirSim/PX4 的 thrust、速度上限、body-rate 参数不能直接用于 Betaflight。
- 实机必须先做无桨、再系留或低速悬停，最后才做受控移动目标测试。

## 6. 当前优先级

1. 完成 Betaflight log-only 台架验证。
2. 标定相机内参、上视外参、端到端延迟和 YOLO 参数。
3. 标定 RC 映射、hover throttle、最大角速度和斜率限制。
4. 使用 CSV 或静态目标做无桨 RC 注入。
5. 与 Betaflight Blackbox 对齐日志，再进入低速系留测试。
