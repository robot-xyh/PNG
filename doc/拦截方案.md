# 上视相机纯视觉导引方案

## 1. 方案目标

本方案对应当前仓库实际实现：用固定上视相机或 AirSim 相机检测目标，通过 bbox 中心估计 LOS，通过 bbox 面积估计接近趋势，再生成可记录、可回放、可受限输出的导引候选量。

当前项目支持三类验证：

- 合成数据和单元测试。
- AirSim/PX4 仿真或 HIL。
- Betaflight MSP telemetry / RC setpoint 台架验证。

## 2. 总体数据流

```text
图像 / AirSim detection / CSV 回放
  -> YOLOv8 + ByteTrack / KCF / AirSim box2D
  -> FrameDetection
  -> 相机内参去归一化
  -> R_BC 固定相机外参
  -> R_IB(t_exposure) 姿态历史查表
  -> 6D LOS Kalman Filter
  -> Scale Expansion TTC
  -> GuidanceEval
  -> AirSim/PX4 或 Betaflight 输出适配
```

## 3. 6D LOS 角度通道

相机是测角传感器，bbox 中心点只用于估计目标方向。

状态：

```text
X = [lambda_x, lambda_y, lambda_z,
     lambda_dot_x, lambda_dot_y, lambda_dot_z]
```

观测：

```text
bbox center -> los_C -> R_BC -> R_IB(t) -> lambda_I_measured
```

输出：

- `lambda_I`
- `lambda_dot_I`
- `omega_los = lambda_I x lambda_dot_I`
- `innovation_norm`
- `quality`
- `valid/reject_reason`

关键约束：

- `lambda_I` 必须归一化。
- `lambda_dot_I` 必须投影到垂直 `lambda_I` 的平面。
- 姿态查表失败、track id 切换、innovation 超限时不输出有效导引。

## 4. TTC 接近趋势通道

bbox 面积只用于独立 TTC 通道，不进入 LOS 主状态。

```text
A = bbox_width * bbox_height
TTC ~= A / A_dot
```

TTC 表示图像尺度膨胀趋势，不等于真实距离或真实闭合速度。以下情况必须拒绝或降权：

- bbox 面积过小。
- bbox 被图像边界裁切。
- 面积突变。
- 目标姿态变化导致面积不再主要反映距离变化。
- track id 不连续。

## 5. 导引评估量

当前 reusable pipeline 使用：

```text
g_eval = K(TTC) * lambda_dot_I
```

其中 `K(TTC)` 是平滑增益调度，TTC 越紧迫，候选导引量权重越高。`g_eval` 不是飞控原生命令，必须经过平台适配层：

- AirSim Blocks：可作为评估量或 bounded motion 输入。
- PX4 SITL/HIL：可进一步转为 velocity、body-rate/thrust 或 attitude/thrust。
- Betaflight：先按曝光时刻姿态计算`g_B=R_IB^T g_I`，再经`rate_gain_matrix`转为
  roll/pitch/yaw rate并映射为RC通道。禁止把惯性系向量直接送入固定机体系矩阵。

## 6. 固定上视相机流程

上视相机的关键问题是视场保持。目标靠近画面边缘、bbox 裁切或检测帧率不足时，继续放大横向导引会导致目标丢失。

当前 AirSim/PX4 strapdown runner 已实现或记录：

- 固定相机外参。
- YOLO/ByteTrack 或 AirSim detection。
- frame centering / upward centering 辅助项。
- terminal image KF。
- clipped bbox 策略。
- blind push / terminal extrapolation。
- body-rate 与 attitude setpoint 诊断。

Betaflight runner 当前只做候选 RC 映射和安全日志，不直接复用 PX4 terminal 控制参数。

## 7. Betaflight 实机适配

Betaflight 不是 PX4 Offboard 架构。当前实现采用：

```text
Betaflight MSP telemetry
  -> attitude/status/analog/RC logging
GuidanceEval
  -> rate_gain_matrix
  -> GuidanceSetpoint
  -> RcCommandMapper
  -> MSP_SET_RAW_RC
```

安全状态机要求：

- `--control-mode msp_raw_rc`
- `--allow-control`
- AUX enable 有效
- 遥测新鲜
- 姿态同步
- 电压正常
- watchdog 正常
- 目标和导引有效

任一条件不满足时不进入 active RC 输出。

当前仓库已有 Betaflight 专用适配优化，位置在 `vision_guidance/flight_control.py` 和
`examples/run_betaflight_log_only.py`：

- `rate_gain_matrix @ g_eval` 只生成 roll/pitch/yaw rate 候选量，不复用 PX4 body-rate。
- `RcCommandMapper` 按 `channel_map` 输出 8 通道 RC，并记录 raw、clipped、slew 三类结果。
- throttle 使用 `thrust_min/hover/max -> throttle_min/hover/max_us` 的分段线性标定。
- `max_delta_us_per_s` 对 RC us 做斜率限制，避免检测抖动直接形成阶跃舵量。
- `BetaflightSafetyStateMachine` 用 telemetry、attitude、voltage、watchdog、AUX 和 target_valid
  共同决定是否 `ACTIVE`。
- 退出或非 active 状态可发送中性 RC，确保失效时不保持上一帧候选命令。

## 8. 日志字段

Betaflight CSV 必须用于阶段验收，重点字段：

- `telemetry_error`, `send_error`
- `safety_state`, `safety_reason`
- `telemetry_age_s`, `attitude_age_s`, `watchdog_age_s`
- `bbox_area_ratio`, `bbox_clipped`
- `los_valid`, `los_innovation_norm`
- `ttc_valid`, `ttc_s`
- `g_eval_x/y/z`
- `rc_in_ch*`, `rc_raw_ch*`, `rc_ch*`
- `rc_clipped_ch*`, `rc_slew_limited_ch*`

日志代码在 `examples/run_betaflight_log_only.py`：

- `_log_fields()` 定义字段并按通道数展开 RC 字段。
- `_log_row()` 将 MSP 遥测、bbox、LOS/TTC、`g_eval`、setpoint、RC 和安全 gate 写入同一行。
- `_write_run_meta()` 记录 `args`、`config`、字段列表和 FC identity。

排查顺序应固定为：MSP 错误 -> safety gate -> 视觉有效性 -> setpoint -> RC 限幅/斜率。

## 9. 方案边界

本方案不假设单目视觉可以可靠测距。实机前必须确认：

- 相机内参和外参。
- 端到端延迟。
- YOLO 真实帧率和漏检率。
- Betaflight rate/expo/PID。
- hover throttle。
- RC 通道方向和 AUX gate。
- `rate_gain_matrix` 符号和增益。

未完成这些确认前，只允许 log-only 或无桨台架验证。
