# Betaflight FLIGHT_ACTIVE / LOG00106 与靶机 ULog 联合分析

## 1. 结论

本架次的 Orange Pi 遥测、拦截机 `LOG00106.BFL` 和靶机 PX4
`10_35_19.ulg` 可以配对到同一次飞行。PNG 实际发布算法指令约 `1.67 s`。靶机在算法发布
窗口内的速度 P95 只有 `0.056 m/s`，N/E/D 端点位移约
`-0.043/+0.035/-0.038 m`，可以判定其平移状态基本静止。拦截机在接管期间建立了明显的向上
闭合速度；算法停止后 `0.902 s`，两机发生实际接触。

双机冲击证据高度一致：靶机 IMU 在 `2026-09-04 10:38:03.350341 UTC` 首次超过
`20 m/s2`，拦截机 Blackbox 在 `10:38:03.352876 UTC` 首次出现电机边界响应，名义时差只有
`2.535 ms`。PX4 的 GNSS 报文发布抖动意味着该数值不能解释为硬件级时间同步精度，但两边在同一
时刻出现冲击、角速度和电机差速，足以确认这是同一次物理碰撞，而不是仅凭单机姿态推测命中。

这次碰撞不是 Roll/Pitch 符号反向、MSP 丢帧或 PNG 发布期间电机饱和造成的：碰撞前的
Betaflight setpoint 到 gyro 跟随相关系数为 `0.991/0.994`，最佳滞后均约 `15 ms`，增益为
`1.027/1.013`；PNG 发布期间四电机 Blackbox raw 范围为 `581--936`，没有触碰
`158/2047` 饱和边界。

不能把碰撞与 PNG 轨迹割裂。接管期间总导引加速度有 `72.6%` 的控制行达到
`7 m/s2` 总上限，速度建立项有 `65.5%` 的控制行饱和；推力模型要求 `1.55--1.74 g`，油门从
接管前 `1303 us` 平滑升到最高 `1396 us`。Blackbox 的 NED 垂直速度从约 `+0.12 m/s`
发展到约 `-4.10 m/s`，即快速向上。算法停止后飞行器依靠惯性继续闭合，因此这是一条由 PNG
建立、退出动作未能及时截断的碰撞轨迹。

靶机并非在碰撞前最后一刻始终保持杆量中位。其接收机在主冲击前约 `0.27 s` 已出现左滚输入，
PX4 归一化 Roll 指令在主冲击前约 `0.127 s` 达到明显幅度，主冲击时靶机 Roll 姿态约
`-2.5 deg`。不过在 PNG 发布期靶机三轴杆量均为零，直到主冲击前其水平速度仍小于
`0.07 m/s`、最后约 `0.23 s` 平移不足厘米量级。因此“静止目标”对主要闭合过程成立，但不能
把末端 `0.27 s` 描述为完全无操作的被动目标。

本架次还暴露出一个直接影响人工接管的操作/架构风险：飞手切换了飞行模式，但 RC7 的
MSP OVERRIDE 仍保持高位约 `1.69 s`。运行时因 `aux_disabled` 停止算法后，只能持续发送接管前
冻结的 `AETR=1500/1500/1303/1500`，不能发送飞手此刻的实时摇杆。碰撞发生在这个冻结窗口内。
因此，切换 ANGLE 不能代替退出 RC7；恢复人工控制的第一动作必须是 RC7 回人工侧。

本架次可以证明控制链能够识别、跟踪、产生正确方向的姿态响应，并实际闭合到目标；靶机日志又
独立证明发生了同一次物理接触。单次接触仍不能证明 `>=80%` 命中率，也不能支持按相同近距
静止目标、相同增益直接重复飞行。

### 2.1 双机时间对齐方法

- Orange Pi 使用 meta 中 `created_unix_s` 与每行 `elapsed_s` 形成 UTC 时间轴。
- 拦截机 Blackbox 使用日志头 `Log start datetime` 和 `time (us)` 相对量形成 UTC 时间轴。
- 靶机 PX4 使用 `vehicle_gps_position.time_utc_usec` 与 ULog `timestamp` 的中位偏移，把 PX4
  单调时钟映射到 UTC。
- 靶机 GNSS 报文发布偏移残差 P5/P95 约为 `-92.8/+70.8 ms`，因此不把名义
  `2.535 ms` 时差解释成独立硬件同步精度。关键依据是两机冲击特征在同一保守
  `+/-0.1 s` 窗口内重合；采用中位时钟映射后，主冲击与电机边界进一步对齐到约 `2.5 ms`。

Blackbox 使用以下方式解码：

```bash
/tmp/betaflight-blackbox-tools/obj/blackbox_decode \
  --unit-rotation raw --merge-gps --save-headers \
  --output-dir /tmp/log00106_decode_raw \
  logs/blackbox_import/LOG00106.BFL
```

当前定制固件写出的 gyro raw 数值与 deg/s 数值一致。不能使用该解码器的
`--unit-rotation deg/s`，因为日志头 `gyro_scale=1` 会导致错误的超大换算值。

Blackbox 零坏帧，约 `807 Hz`；解码器报告 74.51% PID 循环未记录，这是约四分之一循环记录
策略，不是文件损坏。模式名称文本同样受定制固件枚举错位影响，模式判断以主机 MSP
`mode_flags` 和现场读取的 BOXIDS 为准。

### 3.1 飞行模式门控和人工恢复

在 `39.913180 s`，运行时正确识别到 Acro/Rate 门控不再满足，并停止授权算法输出。异步发布器
在下一个约 `20 ms` 周期切回 passthrough。MSP 调度本身没有卡顿。

但此时 Betaflight 的物理 MSP OVERRIDE 模式仍然有效，直到 `41.607515 s` 才解除。在 override
期间，运行时暂停 `MSP_RC` 轮询，`physical_rc_age_s` 从约 `1.86 s` 增长到 `3.47 s`。这段
passthrough 实际发送的是接管前保存值：

```text
AETR = 1500 / 1500 / 1303 / 1500
```

所以：

- `aux_disabled` 能阻止继续发布 PNG 指令。
- 它不能让当前物理摇杆穿过仍然生效的 MSP OVERRIDE。
- 飞手切换 ANGLE 后，Roll/Pitch 变为中位、Throttle 保持旧的 `1303 us`，并未获得实时四通道控制。
- RC7 回人工侧后约一个 RC/MSP 轮询周期，才重新看到飞手油门 `1397--1497 us` 和姿态杆输入。

日志末端出现的 `1500/1555/1450/1500` 是 RC7 已回人工侧后的物理输入 AETR 映射，不是 PNG
命令；其中 `RC5=2000` 对应随后 DISARM。

### 5.1 油门和垂直闭合

油门交接本次按设计工作：

```text
source                         = 1303 us
算法 requested target 范围     = 1367--1396 us
首个算法输出                    = 1305 us
最高输出                        = 1396 us
handover duration              = 0.8 s
```

没有发现旧版本的油门下跳问题，也没有超过 `1500 us` 绝对限制。Blackbox 在算法窗口测得比力
中位约 `1.32 g`、P95 约 `1.45 g`，与增加推力的方向一致。

目标机静止且位于上视相机方向，`velocity_establishing_png` 使用 `fixed_vm=10 m/s` 和
`max_guidance_accel=7 m/s2`。Blackbox 在算法窗口内记录：

- 相对气压高度由约 `1.37 m` 增至约 `3.90 m`；绝对值受日志基准影响，变化量更可信。
- GPS NED `v_d` 从约 `+0.12 m/s` 变到 `-4.10 m/s`，负值代表向上。
- 算法停止后最大向上速度约 `4.57 m/s`。
- 碰撞起点附近仍约为 `v_d=-2.15 m/s`。

这些数据与“静止目标、拦截机向目标快速闭合后接触”的现场事实一致。

靶机 ULog 对该判断提供了独立校验。算法发布的 `1.67 s` 内，靶机：

- 合速度 P50/P95/max 为 `0.042/0.056/0.058 m/s`；
- N/E/D 端点位移为 `-0.043/+0.035/-0.038 m`；
- Roll/Pitch/Yaw 杆量均为零，`sticks_moving=0`；
- Roll/Pitch/Yaw 姿态标准差约为 `0.229/0.144/0.039 deg`。

因此，PNG 主动发布期间可以把靶机视为平移静止目标。需单独注明的是，靶机飞手在主冲击前
约 `0.27 s` 开始给左滚接收机输入，PX4 归一化 Roll 指令在主冲击前约 `0.127 s` 达到明显
幅度，目标在碰撞前已开始滚转。这不改变此前 `1.67 s` 的静止目标判定，但会影响最后约
`0.27 s` 的接触姿态。

### 5.2 接触锚定的双机相对运动

两机本地 NED 原点不同，不能直接相减。这里把已确认的物理接触时刻设为零，只比较两机各自
相对于接触时刻的位置变化。该方法消除了常值原点偏差，但仍受 5 Hz MSP 更新、气压计动态和
机体/天线尺寸影响，所以结果是“到接触还需要闭合的相对位移”，不是精确的机体中心距离。

|时刻|接触锚定结果|
|---|---:|
|PNG 开始|Orange Pi NED 位置给出约 `5.06 m`；Blackbox 气压高度给出约 `6.34 m`|
|PNG 停止|两种来源均给出约 `3.27--3.39 m` 尚待闭合|
|PNG 停止到主冲击|`0.902 s`|

两套高度来源对接管初段的快速爬升存在约 `1.3 m` 分歧，不能据此声称初始距离精确到厘米；
但二者一致表明，算法停止时拦截机与接触位置之间仍有约 `3.3 m` 相对位移，随后靠已建立的
向上速度继续闭合。算法停止时，靶机垂直速度约 `-0.028 m/s`；拦截机气压速度约
`-2.48 m/s`、GPS NED 速度约 `-4.42 m/s`。主冲击附近，拦截机 GPS NED 速度约
`-2.15 m/s`，气压速度约 `-3.47 m/s`，靶机约 `-0.015 m/s`。综合可把接触前向上闭合速度
约束在 `2.1--3.5 m/s`，不应只取其中一个估计器作为无误差真值。

## 6. 碰撞段

Blackbox 在自身时间 `20.673876 s` 首次出现电机边界值。前一采样仍为：

```text
setpoint R/P/Y = -1 / -5 / 0 deg/s
rcCommand R/P/Y = 0 / 0 / 0
gyro R/P/Y = -13 / -3 / +10 deg/s
motor raw = 429 / 664 / 770 / 779
```

下一采样约 `1.26 ms` 后，gyro 变为 `+19/-15/+18 deg/s`，电机变为
`1042/797/691/158`；再约 `25 ms` 后，gyro 和加速度同时出现大冲击，电机触及双侧边界。
这种“陀螺突变 -> D/PID 大差速”的指纹与外部接触相符，而不是先有 PNG 大 setpoint。

|碰撞/恢复段指标|结果|
|---|---:|
|gyro 合成角速度峰值|约 `963 deg/s`|
|比力峰值|`47.48 m/s2`，约 `4.84 g`|
|电机 raw 饱和样本比例|`87.25%`|
|电流 P95/峰值|`54.65/82.06 A`|
|最低电压|`19.76 V`|

碰撞后 Betaflight 在姿态剧烈变化下产生最高 `-547/-435 deg/s` 的自稳 setpoint，并反复把电机
推到 `158/2047`。这些是碰撞后的飞控恢复动作，不能作为 PNG 输出范围统计。主机 5 Hz gyro
和 1 Hz analog 轮询只看到较低的峰值，因此冲击分析以 Blackbox 为准。

碰撞发生在算法发布结束约 `1.0 s` 后，但发生在 RC7 仍保持 MSP OVERRIDE 的冻结窗口内。直接
触发冲击的是物理接触；到达目标的闭合速度由此前 PNG 推力/导引和随后惯性共同形成。

### 6.1 靶机侧碰撞证据

靶机高频 `sensor_combined` 在 `10:38:03.350341 UTC` 首次出现超过 `20 m/s2` 的主冲击，
比拦截机首次电机边界响应名义上早 `2.535 ms`。靶机冲击后 `0.5 s` 指标为：

|靶机指标|结果|
|---|---:|
|比力峰值|`57.30 m/s2`，约 `5.84 g`|
|合成角速度峰值|约 `171.45 deg/s`|
|四电机输出总范围|`591--1044`|
|电机最大极差|`349`|
|电流峰值|`26.82 A`|
|最低电压|`22.18 V`|
|碰撞后 1.5 s 最大水平速度|`1.40 m/s`|
|碰撞后 1.5 s N/E/D 位移|约 `-0.06/-1.05/+0.04 m`|

靶机在碰撞时保持 PX4 `nav_state=2`（Position Control），没有 failsafe。碰撞后仍保持 ARM 和
受控飞行约 `34 s`，然后正常落地并 DISARM。该行为与“目标机受到一次侧向/滚转冲击后由飞手和
PX4 恢复”一致，而不是目标机自身失控先撞向拦截机。

需要区分两段角速度：主冲击前靶机已经响应飞手左滚指令，角速度先超过 `20 deg/s`；
`10:38:03.350 UTC` 开始的多轴比力突变和随后 `5.84 g` 峰值才作为主物理接触证据。仅凭靶机
角速度提前变化，不能把首次轻微接触精确定位到更早时刻。

### 7.1 GPS 相对距离限制

在已经由双机 IMU 确认的物理接触时刻，直接相减两台 GNSS 仍得到约：

- 靶机相对拦截机：北向 `-5.18 m`、东向 `+1.31 m`；
- 水平差约 `5.34 m`；
- MSL/Betaflight 高度直接相减约 `-8.25 m`。

物理接触时不可能存在这样的机体间距。这些残差来自独立接收机偏差、不同高度基准、天线位置、
数据延迟和 Betaflight/PX4 估计链差异。因此本架次不能用两机绝对经纬度直接计算脱靶量，也不能
用该差值否定已经由双机冲击证明的碰撞。相对轨迹只能使用各自位置增量、速度和接触时刻锚定，
并保留米级不确定性。

## 10. 下一步最小处理项

在重复带桨主动接管前，至少需要明确并处理以下三项：

1. 将“RC7 回人工侧”定义为唯一首要退出动作；不能以 ANGLE 开关代替。若仍使用 mask 15，飞手
   必须先退出 RC7，再切换飞行模式。
2. 区分测试目标：若科目要求不碰撞，不能继续使用静止近距目标配合 `Vm=10 m/s`、
   `7 m/s2`；应采用错开航线或降低该科目的速度建立参数。若科目本身要求物理命中，则需要单独
   的末端状态、接触判定和碰撞后停机策略。
3. 增加近距终端门控。至少使用框面积/面积增长率降低或终止 LOS 预测，不能在面积比已达到
   `0.274` 且目标丢失后仍保留约 `0.3 s` 的最大角速度候选。

另外应修复 console/events 尾部 NUL 和 commit 为空的问题，但它们不是本次碰撞原因。
